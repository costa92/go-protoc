## 🎯 架构设计原则

### 1. 清洁架构 (Clean Architecture)
- **分层设计**: Handler → Biz → Store 分层架构
- **依赖反转**: 依赖抽象而非具体实现
- **单一职责**: 每个组件专注单一功能

### 2. 云原生设计
- **容器化**: 全面支持 Docker 容器部署
- **微服务**: 可独立部署和扩展的服务单元
- **可观测性**: 内建监控、日志、链路追踪

### 3. 生产就绪
- **高可用**: 多实例部署和故障转移
- **可扩展**: 水平和垂直扩展支持
- **安全性**: 认证、授权、数据加密

## 🔍 架构决策记录 (ADR)

关键的架构决策和理由：

| 决策 | 选择 | 理由 |
|------|------|------|
| **微服务框架** | Kratos v2 | 成熟的 Go 微服务框架，社区活跃 |
| **依赖注入** | Wire | 编译时依赖注入，性能和安全性更好 |
| **API 协议** | gRPC + HTTP | 高性能 + 兼容性，双协议支持 |
| **数据存储** | MySQL + Redis | 关系型 + 缓存，满足不同场景需求 |
| **可观测性** | OpenTelemetry | 业界标准，多平台兼容 |
